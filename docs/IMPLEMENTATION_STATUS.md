# Implementation status

This file records what the repository demonstrates today. “Implemented” means exercised by the current code and tests; it is not a claim of general Microsoft Word compatibility.

## M0 feasibility gates

| Gate | Current evidence | Status |
|---|---|---|
| Open and byte-identically copy 100 public DOCX fixtures | A synthetic fixture is retained in memory and copied byte for byte, even after its source file is removed. A licensed public corpus has not been assembled. | Partial |
| Edit one supported paragraph without changing unrelated OOXML | A synthetic test replaces one safe `w:t` span and verifies exact `document.xml` locality plus byte preservation of an opaque custom part. | Implemented for the narrow patch path |
| Round-trip paragraphs, styles, lists, tables, images, and sections | Basic direct run/paragraph formatting, authored and imported simple rectangular semantic tables, view-only bounded internal inline raster images, the supported Office Math subset, hard page-break pagination, and one body section's page settings are covered. Semantic OOXML lists, image authoring, advanced tables, and multiple sections are not authored yet. | Not met |
| Unicode shaping, caret, selection, and line breaking across English/RTL/CJK/Indic | The Qt canvas uses `QTextLayout` and grapheme-boundary movement. A multilingual conformance suite is not present. | Partial |
| Same pagination for screen and searchable PDF | Screen, print, and PDF use the canvas's same laid-out page geometry; a smoke test checks PDF text extraction. There is no display-list equality or pagination corpus yet. | Partial |
| Fuzz malformed ZIP/XML/media in a restricted parser | Every GUI open is preflighted by a resource-limited, seccomp-restricted helper with ZIP/XML size, count, and depth ceilings. The GUI reparses the same held descriptor, and no fuzz campaign is present. | Partial |

## Working application slice

- Multi-tab native Qt window, geometric Owl Docs application icon, icon-based ribbon, page canvas, zoom, status, recent files, file association metadata, command palette, find/replace, clipboard, undo/redo, and common editing shortcuts. Typing coalesces into one undo item until a one-second timeout or an editing boundary; double-click selects a word, triple-click selects the visual line, wrapped-line vertical movement preserves the visual column, and printable AltGr input is accepted.
- Font family and size, bold, italic, underline, strikeout, color, highlight, superscript/subscript, alignment/justification, indents, line/paragraph spacing, Normal/Narrow/Moderate/Wide/Office 2003/custom margins, page size, orientation, and page-break controls render in the editing session. Supported terminal imported hard page breaks and Ctrl+Enter breaks produce real page boundaries in the canvas, print, and PDF rather than soft lines; a break followed by content in the same OOXML paragraph remains outside this import subset. New canvases begin with explicit black text and single line spacing. Palette choices apply immediately; the extended picker is non-modal and buttonless, and No Highlight clears highlighting without clearing font color. File > Options persists the default font family, font size, and tab width; tabs default to four space-equivalents for the active font.
- New DOCX serialization currently covers body paragraphs (including tabs and manual line breaks), basic direct run/paragraph formatting, semantic tables with supported cell character/paragraph formatting and built-in table styles, the supported OMML equation subset, one body section's page size and margins, a `styles.xml` part that persists the configured default font and size with single line spacing/no automatic paragraph gap, and a `settings.xml` default tab stop derived from the configured space-equivalent width.
- Imported DOCX files transfer ordered direct body paragraphs, hard page breaks, bounded simple rectangular tables, basic direct run/paragraph formatting, and final body page settings to the canvas. A bounded safe subset of internally related raster inline DrawingML also renders view-only at its declared OOXML extents, subject to proportional reduction to available page width. Original package bytes and opaque members remain available for exact unchanged Save As; very limited mapped one-span paragraph edits can be patched in place without flattening intervening tables or changing preserved image parts.
- Local Hunspell squiggles, context-menu suggestions, ignore/ignore-all, and a local personal dictionary. Keyboard/IME input keeps only the word actively being composed free of a squiggle; whitespace, punctuation, a line/cell boundary, focus loss, or moving outside that word commits it for checking. Imported, pasted, recovered, and Codex-authored text is checked immediately.
- The ribbon and Editor Options retain Qt's complete installed multilingual font-family model but use a family-name-only popup, avoiding Qt's surprising appended native-script samples. Latin-capable families render that clean English name in their own typeface; script-only and symbol families use the UI font so their names remain readable.
- Literal bullet and numbered markers are backed by session-stable per-list metadata: numbered levels cycle through decimal, uppercase alphabetic, uppercase Roman, lowercase alphabetic, and lowercase Roman styles, repeating over ten levels. Toolbar commands toggle/convert selected paragraphs; hierarchical counters restart and resequence; Enter continues the same list; Shift+Enter inserts a visible soft break with its caret and continuation text aligned to the list text stop; Tab nests through ten levels; Shift+Tab outdents; and an empty item terminates the list. Right-clicking a list exposes List Properties, while the active list also exposes a contextual ribbon tab. Bullet positions and post-marker text gaps are independently configurable for levels 1–10 in space-equivalents and affect only the selected list; built-in defaults are 0/4/8/.../36 and two spaces. The dialog can persist the selected list's ten-level geometry as the application default for new lists. Generated DOCX uses explicit text tab stops and hanging indents, which Owl Docs recognizes on reopen, but lists remain ordinary text rather than WordprocessingML numbering definitions.
- Authored and supported imported tables are semantic, ordered body blocks rather than tab-delimited text. For the supported simple import shape, the renderer retains authoritative grid widths and table alignment, cell fills and per-side borders, cell padding, vertical and paragraph alignment, mixed direct run formatting, and Word-compatible automatic row metrics. One insertion dialog collects rows, columns, and optional header status. Activating a cell no longer paints the whole table as selected; drag or Shift-click creates a rectangular multi-cell selection. The ordinary character controls (including font, size, emphasis, color, and highlight) and paragraph alignment/justification work within the active cell or across that selected rectangle, including an empty cell's insertion format. Tab/Shift+Tab traverses cells, Tab in the final cell appends one undoable row, and the contextual Table ribbon inserts or deletes rows/columns and offers 13 built-in styles. The selected table can still be moved earlier/later with its handle or keyboard command. The shared renderer draws tables on screen and in searchable PDFs, while new/simplified DOCX saves and SQLite recovery snapshots retain the supported cell formatting, paragraph formatting, structure, and style. Merged/nested/ragged or multi-paragraph imported tables, merge/split, manual sizing, floating wrapping, and arbitrary imported table-presentation authoring are not yet implemented.
- Safe, bounded raster images referenced by internal `wp:inline` DrawingML relationships render view-only at their positive OOXML extents, with oversized images proportionally reduced to available page width. External relationships, unsafe paths, unsupported media, missing payloads, and over-limit payloads are not loaded. Image authoring/editing, floating or anchored placement, wrapping, crop, and rotation are not supported; the Picture command remains a filename placeholder. Raster decoding still occurs in the GUI process and is an explicit hardening gap.
- Equations are native inline atoms backed by the safe `MathAst`. Fractions, roots, scripts, sums, integrals, delimiters, and six matrix delimiters receive vector layout in the shared page renderer; the supported subset serializes as native OMML and reopens as canonical LaTeX without literal marker text. Unsupported OMML remains outside the editable subset and arbitrary TeX commands, packages, filesystem access, and shell escape are never accepted.
- Print preview, standard system printing (all pages, a page range, or the caret's current page), and atomic PDF export all use the same canvas pagination and page-rendering path. Focused headless tests verify page selection, ordering, page geometry, and extractable text when Poppler utilities are installed.
- Optional app-server chat with user activation, managed account login, dynamically listed model/effort/service-tier values, conservative Standard-speed selection, streaming, local SQLite message storage, and live bounded read/preview dynamic tools. Formatting previews are tracked as such when accepted and become one undo transaction.
- Debounced and periodic SQLite recovery checkpoints restore semantic text, direct formatting, native equation atoms, authored tables and cell IDs, table-cell character/paragraph formatting, selected table styles, body-block order, node IDs, and page geometry. Recovery does not retain an imported file's opaque package objects, so a recovered import can only be written as a warned simplified copy at a destination other than the original.
- Same-path saves fingerprint the opened file and refuse to overwrite an externally changed or unreadable destination; the user must choose Save As instead.

## Explicitly not implemented yet

- Semantic OOXML bullets or multilevel numbering; advanced table operations such as merge/split, nested/floating tables, manual row/column sizing, arbitrary custom border/fill/padding authoring, and multi-paragraph cells; image embedding/authoring/editing, floating or anchored images, text wrapping, crop/rotation, shapes, text boxes, charts, or diagrams. The only current image display path is the bounded internal raster `wp:inline` subset described above.
- Office Math outside the documented safe subset, arbitrary TeX commands/packages/macros, direct equation-source editing after insertion, and Word-complete mathematical typography or compatibility behavior.
- Imported style/theme fidelity in the canvas, headers/footers, footnotes/endnotes, comments, tracked changes, fields, content controls, and editable complex drawings.
- Full-fidelity recovery of imported opaque content, rulers/navigation panes, an AT-SPI document accessibility tree, incremental background pagination, Skia output, and the published performance gates.
- The Unix-socket MCP helper and destination-capability grant flow. Live `editor.v1` dynamic reads/previews are present, while the file-capability tool denies ungranted requests.
- Hunk-by-hunk preview acceptance, idempotency replay caching, and the complete roadmap tool set (`search`, styles, compatibility, page rendering, save/export requests). The current dynamic surface provides bounded semantic reads, one atomic preview operation batch, and a denied-until-granted file capability.
- Corpus-based Word/Google Docs/Pages/LibreOffice interoperability evidence, fuzz campaigns, Word-VM repair checks, signed release packages, complete license review, and an SPDX SBOM.

## Release interpretation

The executable is suitable for engineering evaluation of the architecture and the supported basic-writing slice. It should not be presented as a production word processor, a security-hardened document viewer, or a Word-compatible M1 alpha until the unmet gates above are closed.
