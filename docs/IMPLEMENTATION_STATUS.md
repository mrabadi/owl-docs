# Implementation status

This file records what the repository demonstrates today. “Implemented” means exercised by the current code and tests; it is not a claim of general Microsoft Word compatibility.

Version 0.6.0 combines a compact desktop workspace, expanded safe equation editing, academic writing objects, and source-preserving save/recovery improvements. M0 is complete; remaining M1 daily-use and M2 hardening gates stay active. See `RELEASE_NOTES_0.6.0.md`, `ROADMAP.md`, and the focused `TDD_*_EVIDENCE.md` records for the implementation and validation boundaries.

## Working application slice

- Multi-tab native Qt window, geometric OwlDocs application icon, compact writing toolbar, page canvas, command palette, clipboard, undo/redo, and common editing shortcuts. A successful first open replaces only the untouched startup document; a failed or unsupported command-line ingress leaves it intact. File > Open, positional command-line paths, and the desktop association support multiple documents. File-manager drops open each distinct existing local DOCX with copy-only semantics while skipping remote, non-DOCX, directory, duplicate, and move-only inputs without blocking dialogs; a syntactically eligible file that fails safe parsing is not reported to the drag source as a successful drop. Equivalent paths and symlink aliases activate an existing tab and occupy one recent-file identity. The resolved descriptor target is the save identity, so atomic Save does not replace a symlink even when its target lacks a DOCX extension. Open Recent has numbered entries, directory disambiguation for equal basenames, full-path action data and visible tooltips, nonblocking stale-entry removal, dynamic availability refresh, Remove Missing Documents, and Clear Recent Documents. The modeless Navigation pane keeps search text, replacement text, options, and mode per document tab; it presents debounced live results with snippets in body-paragraph/table-cell order, supports case-sensitive and whole-word matching, activates results only on click or Enter, and navigates from the current caret with `F3`/`Shift+F3`. Replace and Replace All use normal revision-checked operations, with Replace All committed as one undoable editor transaction. Search reads follow the currently visible live or preview snapshot, stale results are rejected by revision and preview-branch identity, and replacement is disabled while a preview is active. The lower-right per-tab zoom slider and synchronized View control cover 25–400%; Control+wheel accumulates standard, high-resolution, and touchpad deltas, while `Ctrl++`, `Ctrl+=`, and `Ctrl+-` are not zoom bindings. Paste as Text Only is available through `Ctrl+Shift+V`, Edit, the command palette, and the document context menu; body and table-cell replacements use destination formatting and one undo transaction. Typing coalesces into one undo item until a one-second timeout or an editing boundary; double-click selects a word, triple-click selects the visual line, wrapped-line vertical movement preserves the visual column, and printable AltGr input is accepted.
- Font family and size, bold, italic, underline, strikeout, color, highlight, superscript/subscript, alignment/justification, indents, line/paragraph spacing, Normal/Narrow/Moderate/Wide/Office 2003/custom margins, page size, orientation, and page-break controls render in the editing session. Supported terminal imported hard page breaks and Ctrl+Enter breaks produce real page boundaries in the canvas, print, and PDF rather than soft lines; a break followed by content in the same OOXML paragraph remains outside this import subset. New canvases begin with explicit black text and single line spacing. Character formatting applied at an empty body paragraph is stored on its semantic paragraph mark, remains active after the caret leaves and returns, survives deletion to empty, every empty-list exit path, recovery, and—for the supported serializable property vocabulary—DOCX reopen, and formats later inserted text. Explicit formatting clears remain clear through live editing and recovery; a null No Highlight override is not yet emitted as an explicit direct OOXML clear. Palette choices apply immediately; the extended picker is non-modal and buttonless, and No Highlight clears highlighting without clearing font color. File > Options persists the default font family, font size, and tab width; tabs default to four space-equivalents for the active font. The More formatting menu exposes Normal, No Spacing, Title, Subtitle, Quote, and Heading 1–9 with preview typography. Normal follows the configured editor font/size; `Ctrl+Shift+N` applies Normal and `Ctrl+Alt+1/2/3` apply Heading 1–3. Enter after a heading applies its configured next style atomically with the split, so one undo restores the original paragraph; Shift+Enter remains a soft break. Named paragraph styles are intentionally unavailable in table cells in this checkpoint.
- Double-clicking the left, center, or right region of any page header/footer edits that region directly on the page; Insert > Header & Footer activates the left header region. The active story exposes three aligned editing surfaces; its story/region, page-field and Close controls are embedded in the contextual ribbon below the writing bar. The document has no floating story toolbar. Changes mirror across every page, while body clicks, Escape and Close restore ordinary writing. `{PAGE}` and `{PAGES}` serialize as native PAGE/NUMPAGES fields, while native center/right paragraph tab stops retain single-line layout. Independently multiline or wrapped regions use deterministic borderless three-cell native tables, with top-aligned headers and bottom-aligned footers. Older sequential multiline or wrapped parts remain exact on unchanged copies and eligible body-text patches; incompatible layout or structural edits require a supported copy. Native parts, content types, relationships, recovery, undo/redo, save/reopen, strict safe-regeneration recognition, and direct-region activation are tested. Rich formatting and first/even/linked or per-section variants remain outside this subset.
- New DOCX serialization covers body paragraphs (including tabs, manual line breaks, durable empty-paragraph insertion properties in `w:pPr/w:rPr`, and supported built-in `w:pStyle` identity), basic direct run/paragraph formatting, native `w:numPr`/`numbering.xml` for list levels 1–9, a visually faithful literal/tab-stop fallback for editor level 10, semantic tables with supported cell character/paragraph formatting and built-in table styles, the supported OMML equation subset, and desktop-authored byte-owned PNG/JPEG DrawingML in the Picture Layout v1 subset. It writes definitions for used built-in paragraph styles, omits inherited style values from direct `w:pPr`/`w:rPr`, and retains explicit direct overrides in the supported writer vocabulary—including equal-by-value and explicit false values—through save/reopen and later style changes. Language metadata and null No Highlight directness remain semantic/recovery-only. It also persists the configured default font and size with single line spacing/no automatic paragraph gap and writes a `settings.xml` default tab stop derived from the configured space-equivalent width. Multiple ordered section authoring remains an engine/API capability that is not exposed by the desktop UI.
- Imported DOCX files transfer ordered direct body paragraphs, paragraph-style IDs with safe resolved-source provenance, supported paragraph-mark character properties, hard page breaks, bounded simple rectangular tables, supported effective formatting from `docDefaults`, `basedOn` style cascades, theme fonts/colors and explicit false values, native numbering semantics, and final-section page settings to the canvas. Cyclic, missing, unsupported, or custom style definitions retain a valid style ID without inventing an unsafe editable baseline. Supported built-in style changes replace inherited source appearance while preserving exact direct run, paragraph-mark, and paragraph overrides. Ordered section metadata for multiple sections is retained by the engine, while the canvas currently applies only its single page-geometry model. Safe internally related raster `wp:inline` drawings and exact canonical zero-offset square/top-and-bottom anchors enter the editable Picture Layout v1 path with their four wrap distances, move/fixed relation, and alt text. Moving anchors use character/paragraph-relative origins; fixed anchors use page/page-relative origins. Inline distance values are retained for fidelity but are not applied by the page layout or exposed as editable controls. Other anchors remain opaque rather than being flattened. Original package bytes and opaque members remain available for exact unchanged Save As; very limited mapped one-span paragraph edits can be patched in place without flattening intervening tables, numbering definitions, or preserved image parts. A complete prepared-package coverage assessment permits supported rich documents to be formatted or structurally edited after reopening. Unrepresented parts, relationships, styles, settings and section properties retain preservation guards. Saved document defaults are independent of application insertion preferences.
- Local Hunspell squiggles, context-menu suggestions, ignore/ignore-all, and a local personal dictionary. Keyboard/IME input keeps only the word actively being composed free of a squiggle; whitespace, punctuation, a line/cell boundary, focus loss, or moving outside that word commits it for checking. Imported, pasted, recovered, and Codex-authored text is checked immediately.
- The writing toolbar and Editor Options retain Qt's complete installed multilingual font-family model but use a family-name-only popup, avoiding Qt's surprising appended native-script samples. Latin-capable families render that clean English name in their own typeface; script-only and symbol families use the UI font so their names remain readable.
- Bulleted and numbered paragraphs are backed by session-stable per-list metadata: numbered levels cycle through decimal, uppercase alphabetic, uppercase Roman, lowercase alphabetic, and lowercase Roman styles, repeating over ten levels. Toolbar commands toggle/convert selected paragraphs; hierarchical counters restart and resequence; Enter continues the same list; Shift+Enter inserts a visible soft break with its caret and continuation text aligned to the list text stop; Tab nests through ten levels; Shift+Tab outdents; and an empty item terminates the list. Right-clicking a list exposes List Properties, while the active list also exposes a contextual row below the writing bar. Bullet positions and post-marker text gaps are independently configurable for levels 1–10 in space-equivalents and affect only the selected list; built-in defaults are 0/4/8/.../36 and two spaces. The dialog can persist the selected list's ten-level geometry as the application default for new lists. Generated DOCX writes standards-valid native numbering definitions and paragraph `w:numPr` for levels 1–9 without duplicating visual markers into text. Editor level 10 uses literal marker text with equivalent tab/hanging geometry and is recovered by OwlDocs on reopen, but is not native continuation semantics in other editors.
- Authored and supported imported tables are ordered semantic body blocks. The Table ribbon exposes row/column insertion/deletion, 13 styles, numeric widths/minimum row heights (Auto = 0), distribution, eight solid/none border presets with color/weight and a direct nine-position horizontal/vertical alignment grid. Dragging cell boundaries previews geometry and commits one undoable operation; no-op/cancel paths preserve the model. A selected cell rectangle limits formatting, while Select Table explicitly targets the whole table. Shared-edge border updates reconcile both neighbors. Compatible imported appearance remains keyed to stable cell identity; authored geometry and direct layout take precedence. Supported metadata, text and inline PNG/JPEG pictures survive core operations, clipboard, conditional schema 16 recovery and native save/reopen/edit/save. Native output uses fixed grids, at-least row heights, per-cell borders and vertical alignment, with complete package reproduction still mandatory. Automatic default tables retain their 0.6.2 representation and older schema 14/15 snapshots retain their existing shape. Merged/nested/ragged/multi-paragraph/equation-bearing/unsupported drawing-bearing tables, exact row heights, row splitting, arbitrary fills/padding and floating tables remain outside this authoring subset.
- Safe, bounded PNG/JPEG images referenced by internal DrawingML relationships become transport-neutral `ImageAtom`s at one U+FFFC paragraph position and render at their positive OOXML extents, with oversized display sizes proportionally reduced to available page width. Picture Layout v1 supports inline placement and two constrained canonical zero-offset forms: square wrapping and top-and-bottom wrapping. Moving anchors use character/paragraph-relative origins; fixed anchors use page/page-relative origins. The semantic record retains top/right/bottom/left wrap distances, move-with-text versus fixed relation, and bounded alt text. Distance controls are editable and visually applied only for anchored layouts; inline distances remain preserved but disabled and have no visual effect. The Picture command inserts the same semantic object rather than filename text. Exact click/range selection, Left/Right collapse, Backspace/Delete, range replacement, Ctrl+A, copy/paste of original bytes, a ratio-lockable size dialog, three persistable on-canvas resize handles (right, bottom, and bottom-right), layout/alt-text dialogs, revisions, previews, and undo/redo use the normal document-operation path. Stable identity, bytes, format, accessible name, EMU dimensions, supported layout, and mixed text/equation/image order survive schema-v14 recovery, native DrawingML save, and desktop reopen; no arbitrary source path is stored. Inputs are limited to 512 images, 16 MiB encoded per image, and 32 MiB aggregate, with separate container, dimension, pixel, decoded-byte, and decoded-cache limits. External relationships, unsafe paths, unsupported media, missing payloads, over-limit payloads, and noncanonical anchors are not exposed as editable images. Crop, rotation, z-order, arbitrary horizontal/vertical positioning, and tight/through/behind/in-front wrapping remain unsupported. Bounded inline PNG/JPEG pictures inside supported cells participate in native transport, selection, editing, undo, clipboard and version-15 semantic recovery. Raster inspection runs before decode, but the actual decode still occurs in the GUI process and is an explicit hardening gap.
- Equations remain non-executing native math atoms with vector screen/PDF layout and OMML persistence. A source editor previews equations live and updates their existing identity and formatting atomically. Added text/font/operator commands, accents, spacing, products, aligned and cases complement fractions, roots, scripts, sums, integrals, delimiters and matrices; generic TeX programs, packages and complete `.tex` document editing remain outside scope.
- Academic primitives include plain-text footnotes/endnotes, document-wide decimal note numbering, captions, heading/caption cross-references, manual numeric bibliography/citations, and generated TOCs. Supported native notes, SEQ/REF/TOC fields and deterministic bookmarks carry cached results. A bounded semantic registry is accepted only with complete source-member verification; generic foreign field/academic constructs remain preservation-only. See the academic TDD evidence for exact tested coverage.
- Print preview, standard system printing (all pages, a page range, or the caret's current page), and atomic PDF export all use the same canvas pagination and page-rendering path. Focused headless tests verify page selection, ordering, page geometry, and extractable text when Poppler utilities are installed.
- Codex authoring tools cover supported tables/cells, body/cell/story pictures,
  regional headers/footers, paragraph structure and formatting, lists,
  single-section page settings, equations, academic objects and editable
  Excalidraw figures. A shared capability catalog supplies schemas and bounds;
  body/cell paragraph formatting and list edits share native editor semantics.
  Complete document reads include empty structural blocks with continuation,
  formatting, image identity and bounded native scene context. Combined
  content/page-layout proposals preserve preview isolation and one-step undo.
  See `CODEX_AUTHORING.md` for the exact supported subset.

- Optional app-server chat with user activation, managed account login, dynamically listed model/effort/service-tier values, conservative Standard-speed selection, streaming multi-turn conversations, local SQLite message storage, and live bounded read, deterministic paragraph/table-cell search, and preview dynamic tools. Completing or failing a turn deterministically restores the composer, and later messages use `turn/start` on the same in-memory document thread; restored mappings use `thread/resume` before continuing. Document-mode instructions and the preview tool description name the supported `set_text_style` and `set_paragraph_style` formatting vocabulary and direct the agent to create a preview rather than merely describing formatting steps. The controller opts into the currently pinned experimental surface by sending `capabilities.experimentalApi=true` in `initialize`, then calls `config/read`, requires a recognized MCP-server map, and constructs a per-thread override containing only inherited MCP names with `enabled=false`. The same isolation is applied to thread start and resume; an absent or malformed map fails closed before account or model discovery. Stderr tracing is discarded instead of becoming a false chat error, while structured protocol/request/write/exit failures remain active. Fake-process tests enforce this sequence, same-thread continuation, and fail-closed behavior, and an optional CTest check validates `config/read`, thread config, dynamic tools, and tool-call fields against an installed runtime. Hosts without Codex/Python skip that installed-schema check, and an absent or incompatible Codex runtime does not affect offline editing. Search ranges and context are grapheme-safe UTF-16, whole-word boundaries are computed once per block, and a returned table-cell identity can be expanded with an explicit typed read target. Persisted server-thread mappings are invalidated when the dynamic-tool catalog changes because the pinned protocol cannot replace that catalog on resume; local chat messages are retained. The `set_paragraph_style` operation exposes the stable built-in style IDs and uses the same provenance-aware transition planner and configured defaults as the formatting controls; explicit properties in the requested operation are applied after that baseline transition. Formatting previews are tracked as such when accepted and become one undo transaction.
- Debounced and periodic recovery retains semantic formatting, objects, academic references and identity. SQLite journals remain schema 14; semantic payloads use version 16 for nonempty table geometry/cell layout, version 15 for cell pictures alone and version 14 otherwise; legacy versions remain readable. Transactional SQLite source journals additionally retain exact original DOCX BLOBs and independently checksummed context. Restoring a deleted or replaced source reparses the retained package through the restricted worker and reconstructs its original source mappings. Safe text edits preserve opaque members in a new destination. Legacy semantic-only journals remain recoverable as supported copies; invalid retained source data is diagnosed and its checkpoint retained.
- Saves compare size plus SHA-256 content rather than timestamps, recheck the destination after candidate validation, and commit by atomic rename. A completed rename followed by a directory-sync error is saved with a durability warning. The editor uses validated committed bytes as its baseline, and cancelled partial patch attempts are discarded before conversion can be offered.
- Imported documents needing conversion offer an explicitly confirmed editable copy with concrete loss details. The original path, symlink aliases and existing hard links are protected. Successfully regenerated supported documents become a native baseline; ordinary later saves do not repeat conversion prompts.
- The first M2 Excalidraw vertical slice is functional and self-contained.

## Explicitly not implemented yet

- Multiple-section desktop authoring; general floating-picture positioning; crop, rotation, z-order, tight/through/behind/in-front wrapping; shapes, text boxes, charts, or diagrams. Picture Layout v1 is limited to inline placement and canonical zero-offset square/top-and-bottom forms with the relative origins described above; it is not an arbitrary anchor/layout engine. Advanced table operations such as merge/split, nested/floating tables, exact row heights, row splitting across pages, non-solid borders, arbitrary fill/padding authoring, and multi-paragraph cells also remain unimplemented.
- Office Math outside the documented safe subset, arbitrary TeX commands/packages/macros, full `.tex` document compilation, and Word-complete mathematical typography or compatibility behavior.
- Style/theme behavior outside the supported `docDefaults`/`basedOn`/theme font-and-color cascade and built-in paragraph-style catalog; custom style-definition authoring/editing; named styles inside table cells; rich or section-specific headers/footers, rich/section-specific or generic foreign note structures, comments, tracked changes, general fields, content controls, and editable complex drawings.
- Rulers, an AT-SPI document accessibility tree, incremental background pagination, Skia output, and the published performance gates. The current Navigation pane covers text search and replacement across body paragraphs and supported semantic table cells; the first heading outline is available, while broader page/object browsing remains future work.
- The separate Unix-socket MCP helper and destination/file-capability grant flow. The live path-free `editor.v1` tools support bounded base64 PNG/JPEG insertion and native Excalidraw generation; they do not expose filesystem access. No file-capability tool is registered in the current catalog. Legacy calls receive an explicit denial.
- Hunk-by-hunk preview acceptance, idempotency replay caching and remaining roadmap tools such as compatibility inspection, page-image reads and save/export requests. The current catalog supplies bounded semantic reads/search, live capability/schema discovery and one atomic preview batch spanning the supported document-authoring subset. File saving and exporting remain manual.
- Cross-producer Word/Google Docs/Pages interoperability breadth beyond the initial pinned LibreOffice preservation corpus, persistent coverage-guided fuzz campaigns, Word-VM repair checks, signed release packages, complete license review, and an SPDX SBOM.

## Release interpretation

Version 0.6.4 continues the broader daily-use development release, with a single-row table ribbon and grouped dropdowns, embedded header/footer controls, direct table geometry, cell positioning and borders alongside the existing academic, math and source-preserving workflows. The remaining gates still include broad cross-producer layout fidelity, performance targets, helper-process hardening, final private OPC figure representation, accessibility and signed reproducible releases. No Word-class parity claim is made.
