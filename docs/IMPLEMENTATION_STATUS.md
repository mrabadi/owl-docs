# Implementation status

This file records what the repository demonstrates today. “Implemented” means exercised by the current code and tests; it is not a claim of general Microsoft Word compatibility.

M0 is complete and M1 daily-use alpha work is active. The accepted milestone
sequence, including local editable Excalidraw figures as M2, is maintained in
`ROADMAP.md`.

## M0 feasibility gates

| Gate | Current evidence | Status |
|---|---|---|
| Open and byte-identically copy 100 public DOCX fixtures | The reproducible external-corpus runner opened and byte-identically copied 100/100 deterministically selected LibreOffice `ooxmlexport` DOCX fixtures from pinned commit `2776654bbb109af114a44fe00ec9771e4ad2d99d` (MPL-2.0). Raster decoding still runs in the GUI process rather than a restricted helper. | Met for the initial bounded/fuzz-smoke gate; decoder isolation remains open |

## Working application slice

- Multi-tab native Qt window, geometric Owl Docs application icon, icon-based ribbon, page canvas, command palette, clipboard, undo/redo, and common editing shortcuts. A successful first open replaces only the untouched startup document; a failed or unsupported command-line ingress leaves it intact. File > Open, positional command-line paths, and the desktop association support multiple documents. File-manager drops open each distinct existing local DOCX with copy-only semantics while skipping remote, non-DOCX, directory, duplicate, and move-only inputs without blocking dialogs; a syntactically eligible file that fails safe parsing is not reported to the drag source as a successful drop. Equivalent paths and symlink aliases activate an existing tab and occupy one recent-file identity. The resolved descriptor target is the save identity, so atomic Save does not replace a symlink even when its target lacks a DOCX extension. Open Recent has numbered entries, directory disambiguation for equal basenames, full-path action data and visible tooltips, nonblocking stale-entry removal, dynamic availability refresh, Remove Missing Documents, and Clear Recent Documents. The modeless Navigation pane keeps search text, replacement text, options, and mode per document tab; it presents debounced live results with snippets in body-paragraph/table-cell order, supports case-sensitive and whole-word matching, activates results only on click or Enter, and navigates from the current caret with `F3`/`Shift+F3`. Replace and Replace All use normal revision-checked operations, with Replace All committed as one undoable editor transaction. Search reads follow the currently visible live or preview snapshot, stale results are rejected by revision and preview-branch identity, and replacement is disabled while a preview is active. The lower-right per-tab zoom slider and synchronized View control cover 25–400%; Control+wheel accumulates standard, high-resolution, and touchpad deltas, while `Ctrl++`, `Ctrl+=`, and `Ctrl+-` are not zoom bindings. Paste as Text Only is available through `Ctrl+Shift+V`, Edit, the command palette, and the document context menu; body and table-cell replacements use destination formatting and one undo transaction. Typing coalesces into one undo item until a one-second timeout or an editing boundary; double-click selects a word, triple-click selects the visual line, wrapped-line vertical movement preserves the visual column, and printable AltGr input is accepted.
- Font family and size, bold, italic, underline, strikeout, color, highlight, superscript/subscript, alignment/justification, indents, line/paragraph spacing, Normal/Narrow/Moderate/Wide/Office 2003/custom margins, page size, orientation, and page-break controls render in the editing session. Supported terminal imported hard page breaks and Ctrl+Enter breaks produce real page boundaries in the canvas, print, and PDF rather than soft lines; a break followed by content in the same OOXML paragraph remains outside this import subset. New canvases begin with explicit black text and single line spacing. Character formatting applied at an empty body paragraph is stored on its semantic paragraph mark, remains active after the caret leaves and returns, survives deletion to empty, every empty-list exit path, recovery, and—for the supported serializable property vocabulary—DOCX reopen, and formats later inserted text. Explicit formatting clears remain clear through live editing and recovery; a null No Highlight override is not yet emitted as an explicit direct OOXML clear. Palette choices apply immediately; the extended picker is non-modal and buttonless, and No Highlight clears highlighting without clearing font color. File > Options persists the default font family, font size, and tab width; tabs default to four space-equivalents for the active font. The Home ribbon exposes Normal, No Spacing, Title, Subtitle, Quote, and Heading 1–9 with preview typography. Normal follows the configured editor font/size; `Ctrl+Shift+N` applies Normal and `Ctrl+Alt+1/2/3` apply Heading 1–3. Enter after a heading applies its configured next style atomically with the split, so one undo restores the original paragraph; Shift+Enter remains a soft break. Named paragraph styles are intentionally unavailable in table cells in this checkpoint.
- New DOCX serialization covers body paragraphs (including tabs, manual line breaks, durable empty-paragraph insertion properties in `w:pPr/w:rPr`, and supported built-in `w:pStyle` identity), basic direct run/paragraph formatting, native `w:numPr`/`numbering.xml` for list levels 1–9, a visually faithful literal/tab-stop fallback for editor level 10, semantic tables with supported cell character/paragraph formatting and built-in table styles, the supported OMML equation subset, and desktop-authored byte-owned PNG/JPEG DrawingML in the Picture Layout v1 subset. It writes definitions for used built-in paragraph styles, omits inherited style values from direct `w:pPr`/`w:rPr`, and retains explicit direct overrides in the supported writer vocabulary—including equal-by-value and explicit false values—through save/reopen and later style changes. Language metadata and null No Highlight directness remain semantic/recovery-only. It also persists the configured default font and size with single line spacing/no automatic paragraph gap and writes a `settings.xml` default tab stop derived from the configured space-equivalent width. Multiple ordered section authoring remains an engine/API capability that is not exposed by the desktop UI.
- Imported DOCX files transfer ordered direct body paragraphs, paragraph-style IDs with safe resolved-source provenance, supported paragraph-mark character properties, hard page breaks, bounded simple rectangular tables, supported effective formatting from `docDefaults`, `basedOn` style cascades, theme fonts/colors and explicit false values, native numbering semantics, and final-section page settings to the canvas. Cyclic, missing, unsupported, or custom style definitions retain a valid style ID without inventing an unsafe editable baseline. Supported built-in style changes replace inherited source appearance while preserving exact direct run, paragraph-mark, and paragraph overrides. Ordered section metadata for multiple sections is retained by the engine, while the canvas currently applies only its single page-geometry model. Safe internally related raster `wp:inline` drawings and exact canonical zero-offset square/top-and-bottom anchors enter the editable Picture Layout v1 path with their four wrap distances, move/fixed relation, and alt text. Moving anchors use character/paragraph-relative origins; fixed anchors use page/page-relative origins. Inline distance values are retained for fidelity but are not applied by the page layout or exposed as editable controls. Other anchors remain opaque rather than being flattened. Original package bytes and opaque members remain available for exact unchanged Save As; very limited mapped one-span paragraph edits can be patched in place without flattening intervening tables, numbering definitions, or preserved image parts. A reopened paragraph-only package that exactly matches Owl Docs' current writer grammar can also be formatted or structurally edited and saved normally. Any extra part, relationship, style/setting variation, unsupported section property, or changed serialization default re-arms the preservation guard.
- Local Hunspell squiggles, context-menu suggestions, ignore/ignore-all, and a local personal dictionary. Keyboard/IME input keeps only the word actively being composed free of a squiggle; whitespace, punctuation, a line/cell boundary, focus loss, or moving outside that word commits it for checking. Imported, pasted, recovered, and Codex-authored text is checked immediately.
- The ribbon and Editor Options retain Qt's complete installed multilingual font-family model but use a family-name-only popup, avoiding Qt's surprising appended native-script samples. Latin-capable families render that clean English name in their own typeface; script-only and symbol families use the UI font so their names remain readable.
- Bulleted and numbered paragraphs are backed by session-stable per-list metadata: numbered levels cycle through decimal, uppercase alphabetic, uppercase Roman, lowercase alphabetic, and lowercase Roman styles, repeating over ten levels. Toolbar commands toggle/convert selected paragraphs; hierarchical counters restart and resequence; Enter continues the same list; Shift+Enter inserts a visible soft break with its caret and continuation text aligned to the list text stop; Tab nests through ten levels; Shift+Tab outdents; and an empty item terminates the list. Right-clicking a list exposes List Properties, while the active list also exposes a contextual ribbon tab. Bullet positions and post-marker text gaps are independently configurable for levels 1–10 in space-equivalents and affect only the selected list; built-in defaults are 0/4/8/.../36 and two spaces. The dialog can persist the selected list's ten-level geometry as the application default for new lists. Generated DOCX writes standards-valid native numbering definitions and paragraph `w:numPr` for levels 1–9 without duplicating visual markers into text. Editor level 10 uses literal marker text with equivalent tab/hanging geometry and is recovered by Owl Docs on reopen, but is not native continuation semantics in other editors.
- Authored and supported imported tables are semantic, ordered body blocks rather than tab-delimited text. For the supported simple text-table import shape, the renderer retains authoritative grid widths and table alignment, cell fills and per-side borders, cell padding, vertical and paragraph alignment, mixed direct run and paragraph-mark formatting, and Word-compatible automatic row metrics. One insertion dialog collects rows, columns, and optional header status. Activating a cell no longer paints the whole table as selected; drag or Shift-click creates a rectangular multi-cell selection. The ordinary character controls (including font, size, emphasis, color, and highlight) and paragraph alignment/justification work within the active cell or across that selected rectangle. Empty-cell insertion formatting persists across Tab/Shift+Tab navigation and deletion to empty. Tab in the final cell appends one undoable row, and the contextual Table ribbon inserts or deletes rows/columns and offers 13 built-in styles. The selected table can still be moved earlier/later with its handle or keyboard command. The shared renderer draws tables on screen and in searchable PDFs, while new/simplified DOCX saves and SQLite recovery snapshots retain the supported cell run, paragraph-mark, and paragraph formatting, structure, and style. Merged, nested, ragged, multi-paragraph, equation-bearing, or image-bearing imported tables remain preserved view-only; merge/split, manual sizing, floating wrapping, and arbitrary imported table-presentation authoring are not yet implemented.
- Safe, bounded PNG/JPEG images referenced by internal DrawingML relationships become transport-neutral `ImageAtom`s at one U+FFFC paragraph position and render at their positive OOXML extents, with oversized display sizes proportionally reduced to available page width. Picture Layout v1 supports inline placement and two constrained canonical zero-offset forms: square wrapping and top-and-bottom wrapping. Moving anchors use character/paragraph-relative origins; fixed anchors use page/page-relative origins. The semantic record retains top/right/bottom/left wrap distances, move-with-text versus fixed relation, and bounded alt text. Distance controls are editable and visually applied only for anchored layouts; inline distances remain preserved but disabled and have no visual effect. The Picture command inserts the same semantic object rather than filename text. Exact click/range selection, Left/Right collapse, Backspace/Delete, range replacement, Ctrl+A, copy/paste of original bytes, a ratio-lockable size dialog, three persistable on-canvas resize handles (right, bottom, and bottom-right), layout/alt-text dialogs, revisions, previews, and undo/redo use the normal document-operation path. Stable identity, bytes, format, accessible name, EMU dimensions, supported layout, and mixed text/equation/image order survive schema-v11 recovery, native DrawingML save, and desktop reopen; no arbitrary source path is stored. Inputs are limited to 512 images, 16 MiB encoded per image, and 32 MiB aggregate, with separate container, dimension, pixel, decoded-byte, and decoded-cache limits. External relationships, unsafe paths, unsupported media, missing payloads, over-limit payloads, and noncanonical anchors are not exposed as editable images. Crop, rotation, z-order, arbitrary horizontal/vertical positioning, tight/through/behind/in-front wrapping, and pictures inside table cells are not supported. Raster inspection runs before decode, but the actual decode still occurs in the GUI process and is an explicit hardening gap.
- Equations are native inline atoms backed by the safe `MathAst`. Fractions, roots, scripts, sums, integrals, delimiters, and six matrix delimiters receive vector layout in the shared page renderer; the supported subset serializes as native OMML and reopens as canonical LaTeX without literal marker text. Unsupported OMML remains outside the editable subset and arbitrary TeX commands, packages, filesystem access, and shell escape are never accepted.
- Print preview, standard system printing (all pages, a page range, or the caret's current page), and atomic PDF export all use the same canvas pagination and page-rendering path. Focused headless tests verify page selection, ordering, page geometry, and extractable text when Poppler utilities are installed.
- Optional app-server chat with user activation, managed account login, dynamically listed model/effort/service-tier values, conservative Standard-speed selection, streaming multi-turn conversations, local SQLite message storage, and live bounded read, deterministic paragraph/table-cell search, and preview dynamic tools. Completing or failing a turn deterministically restores the composer, and later messages use `turn/start` on the same in-memory document thread; restored mappings use `thread/resume` before continuing. Document-mode instructions and the preview tool description name the supported `set_text_style` and `set_paragraph_style` formatting vocabulary and direct the agent to create a preview rather than merely describing formatting steps. The controller opts into the currently pinned experimental surface by sending `capabilities.experimentalApi=true` in `initialize`, then calls `config/read`, requires a recognized MCP-server map, and constructs a per-thread override containing only inherited MCP names with `enabled=false`. The same isolation is applied to thread start and resume; an absent or malformed map fails closed before account or model discovery. Stderr tracing is discarded instead of becoming a false chat error, while structured protocol/request/write/exit failures remain active. Fake-process tests enforce this sequence, same-thread continuation, and fail-closed behavior, and an optional CTest check validates `config/read`, thread config, dynamic tools, and tool-call fields against an installed runtime. Hosts without Codex/Python skip that installed-schema check, and an absent or incompatible Codex runtime does not affect offline editing. Search ranges and context are grapheme-safe UTF-16, whole-word boundaries are computed once per block, and a returned table-cell identity can be expanded with an explicit typed read target. Persisted server-thread mappings are invalidated when the dynamic-tool catalog changes because the pinned protocol cannot replace that catalog on resume; local chat messages are retained. The `set_paragraph_style` operation exposes the stable built-in style IDs and uses the same provenance-aware transition planner and configured defaults as the ribbon; explicit properties in the requested operation are applied after that baseline transition. Formatting previews are tracked as such when accepted and become one undo transaction.
- Debounced and periodic SQLite recovery checkpoints use schema v11. They restore semantic text, direct formatting, paragraph-style identity, distinct inherited text/paragraph-mark baselines, exact override provenance, durable body-paragraph mark/insertion formatting, native equation atoms, PNG/JPEG picture source, geometry, supported Picture Layout v1 values and alt text, authored tables and cell IDs, table-cell character/paragraph formatting, selected table styles, body-block order, node IDs, and page geometry. Legacy decode paths remain in place, with targeted migration fixtures covering versions 3–10; absent paragraph-mark, picture-layout, style-ID, and provenance fields take safe empty, inline, or provenance-free defaults, while v10 style provenance derives its missing paragraph-mark baseline from its prior text baseline. Recovery does not retain an imported file's other opaque package objects, so saving a recovered import requires the same explicit compatibility warning before Owl Docs writes a supported-subset document, whether to the original path or a new destination.
- Same-path saves fingerprint the opened file and refuse to overwrite an externally changed or unreadable destination; the user must choose Save As instead.
- Imported documents that require supported-subset regeneration show one
  explicit compatibility/loss warning per document session. After the user
  chooses Save Anyway, Owl Docs may atomically overwrite the original or write
  a new destination; a successful rebuild becomes the new native baseline and
  does not repeat the warning on later saves. External-change conflicts remain
  a hard Save As requirement.
- The first M2 Excalidraw vertical slice is functional and self-contained.
  Insert > Excalidraw Figure launches the pinned editor shipped inside Owl Docs,
  not a separately installed application. It has no independent open/save
  dialogs or document store. A permission-0700, capability-token session
  returns bounded scene JSON plus a PNG while bubblewrap removes networking and
  leaves only that session writable. The original fork's immediate Sketch and
  Professional modes, professional palette, architect strokes, font and arrow
  defaults are available from both the toolbar and Settings menu; the selected
  mode persists locally in Owl Docs. Each figure's scene is stored as inert
  private PNG iTXt metadata, so the ordinary image object remains visible in
  other DOCX consumers while Owl Docs can reopen it by double-click, F2, context
  menu, or Picture ribbon. Create/update is one transaction; tests cover PNG
  validity, metadata replacement, undo/redo, recovery, and byte-exact native
  DOCX save/reopen. Codex can insert or replace these editable scenes through
  revision-checked preview operations; agent-authored scenes are always locally
  rendered in Professional mode and remain editable. Private OPC-part migration, external-editor flattening
  diagnostics, copy/paste/multi-figure UI automation, and the full M2 security
  gate remain open.

## Explicitly not implemented yet

- Multiple-section desktop authoring; general floating-picture positioning; crop, rotation, z-order, tight/through/behind/in-front wrapping; shapes, text boxes, charts, or diagrams. Picture Layout v1 is limited to inline placement and canonical zero-offset square/top-and-bottom forms with the relative origins described above; it is not an arbitrary anchor/layout engine. Advanced table operations such as merge/split, nested/floating tables, manual row/column sizing, arbitrary custom border/fill/padding authoring, and multi-paragraph cells also remain unimplemented.
- Office Math outside the documented safe subset, arbitrary TeX commands/packages/macros, direct equation-source editing after insertion, and Word-complete mathematical typography or compatibility behavior.
- Style/theme behavior outside the supported `docDefaults`/`basedOn`/theme font-and-color cascade and built-in paragraph-style catalog; custom style-definition authoring/editing; named styles inside table cells; headers/footers, footnotes/endnotes, comments, tracked changes, fields, content controls, and editable complex drawings.
- Full-fidelity recovery of imported opaque content, rulers, an AT-SPI document accessibility tree, incremental background pagination, Skia output, and the published performance gates. The current Navigation pane covers text search and replacement across body paragraphs and supported semantic table cells; heading/page/object browsing remains future work.
- The Unix-socket MCP helper and destination/image-capability grant flow. Live `editor.v1` dynamic reads/previews are present, but the current file-capability tool denies every request because no grant path exists yet. Image insertion is not advertised to Codex until that path can supply a usable capability.
- Hunk-by-hunk preview acceptance, idempotency replay caching, and the remaining roadmap tool set (compatibility, page rendering, save/export requests). The current dynamic surface provides bounded semantic reads, bounded deterministic search, built-in paragraph-style operations, one atomic preview operation batch, and an always-denied file-capability read.
- Cross-producer Word/Google Docs/Pages interoperability breadth beyond the initial pinned LibreOffice preservation corpus, persistent coverage-guided fuzz campaigns, Word-VM repair checks, signed release packages, complete license review, and an SPDX SBOM.

## Release interpretation

Version 0.5.10 is an M1 development checkpoint with the first self-contained M2
Excalidraw vertical slice. It retains the tested 0.4.4 paragraph-style,
multi-document, navigation, zoom, text-only paste, conservative-save, and Codex
isolation work. The gates remain narrower than production acceptance: they do
not establish broad cross-producer layout fidelity, M1 performance targets,
complete helper-process hardening, the final private OPC figure representation,
or Word-class behavior. This release is for engineering evaluation and is not a
complete M1 or M2 release.
