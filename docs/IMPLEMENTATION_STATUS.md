# Implementation status

This file records what the repository demonstrates today. “Implemented” means exercised by the current code and tests; it is not a claim of general Microsoft Word compatibility.

## M0 feasibility gates

| Gate | Current evidence | Status |
|---|---|---|
| Open and byte-identically copy 100 public DOCX fixtures | The reproducible external-corpus runner opened and byte-identically copied 100/100 deterministically selected LibreOffice `ooxmlexport` DOCX fixtures from pinned commit `2776654bbb109af114a44fe00ec9771e4ad2d99d` (MPL-2.0). Each download is checked against its Git blob ID and recorded SHA-256. Password-encrypted `Encrypted_*` CFB containers are excluded as an explicit product boundary rather than counted as successes. | Met for the initial public corpus |
| Edit one supported paragraph without changing unrelated OOXML | The corpus runner's localized-edit mode verifies that a selected safe patch changes only one `w:t` node and that every other package member has identical uncompressed bytes. A deterministic synthetic fixture exercises this mode, opaque-member preservation, and save/reopen behavior in CI. | Met for the narrow patch path |
| Round-trip paragraphs, styles, lists, tables, images, and sections | Targeted synthetic round trips cover paragraph/style formatting, native `numbering.xml` lists, semantic tables, byte-owned internal PNG/JPEG `wp:inline` drawings, and ordered multiple sections with distinct break kinds and page geometry. Image and multiple-section authoring are OOXML engine/API capabilities only; their desktop editing UI is not implemented. | Met at the native engine/API feasibility layer |
| Unicode shaping, caret, selection, and line breaking across English/RTL/CJK/Indic | Headless canvas conformance tests require valid, non-missing shaped glyph runs and exercise grapheme-safe caret movement/selection plus visual-line wrapping for English, RTL Hebrew, CJK, and Indic samples, including RTL editing in a table cell. This validates the current Qt text stack, not every script/font combination. | Met for the representative M0 samples |
| Same pagination for screen and searchable PDF | Screen, print, and PDF consume the canvas's same laid-out page geometry. A soft-flow fixture maps 48 markers to canvas pages, requires the searchable PDF to place each marker on the same page, and verifies that PDF export does not increment the layout generation. This is a simple shared-pagination gate, not a Word pagination corpus. | Met for the M0 fixture |
| Fuzz malformed ZIP/XML/media in a restricted parser | Resource, ZIP/XML structure, truncation, and deterministic mutation fixtures run through the resource-limited, seccomp-restricted parser child and require bounded diagnostics/output and clean exit. PNG/JPEG decoding has strict preflight/decode limits plus malformed, bomb-header, mutation, truncation, and random-byte tests. Raster decoding still runs in the GUI process rather than a restricted helper. | Met for the initial bounded/fuzz-smoke gate; decoder isolation remains open |

## Working application slice

- Multi-tab native Qt window, geometric Owl Docs application icon, icon-based ribbon, page canvas, zoom, status, recent files, file association metadata, command palette, find/replace, clipboard, undo/redo, and common editing shortcuts. Typing coalesces into one undo item until a one-second timeout or an editing boundary; double-click selects a word, triple-click selects the visual line, wrapped-line vertical movement preserves the visual column, and printable AltGr input is accepted.
- Font family and size, bold, italic, underline, strikeout, color, highlight, superscript/subscript, alignment/justification, indents, line/paragraph spacing, Normal/Narrow/Moderate/Wide/Office 2003/custom margins, page size, orientation, and page-break controls render in the editing session. Supported terminal imported hard page breaks and Ctrl+Enter breaks produce real page boundaries in the canvas, print, and PDF rather than soft lines; a break followed by content in the same OOXML paragraph remains outside this import subset. New canvases begin with explicit black text and single line spacing. Palette choices apply immediately; the extended picker is non-modal and buttonless, and No Highlight clears highlighting without clearing font color. File > Options persists the default font family, font size, and tab width; tabs default to four space-equivalents for the active font.
- New DOCX serialization covers body paragraphs (including tabs and manual line breaks), basic direct run/paragraph formatting, native `w:numPr`/`numbering.xml` for list levels 1–9, a visually faithful literal/tab-stop fallback for editor level 10, semantic tables with supported cell character/paragraph formatting and built-in table styles, the supported OMML equation subset, a `styles.xml` part that persists the configured default font and size with single line spacing/no automatic paragraph gap, and a `settings.xml` default tab stop derived from the configured space-equivalent width. The OOXML engine/API can additionally author byte-owned PNG/JPEG inline DrawingML and multiple ordered sections; those two capabilities are not exposed by the desktop authoring UI yet.
- Imported DOCX files transfer ordered direct body paragraphs, hard page breaks, bounded simple rectangular tables, supported effective formatting from `docDefaults`, `basedOn` style cascades, theme fonts/colors and explicit false values, native numbering semantics, and final-section page settings to the canvas. Ordered section metadata for multiple sections is retained by the engine, while the canvas currently applies only its single page-geometry model. A bounded safe subset of internally related raster inline DrawingML also renders view-only at its declared OOXML extents, subject to proportional reduction to available page width. Original package bytes and opaque members remain available for exact unchanged Save As; very limited mapped one-span paragraph edits can be patched in place without flattening intervening tables, numbering definitions, or preserved image parts.
- Local Hunspell squiggles, context-menu suggestions, ignore/ignore-all, and a local personal dictionary. Keyboard/IME input keeps only the word actively being composed free of a squiggle; whitespace, punctuation, a line/cell boundary, focus loss, or moving outside that word commits it for checking. Imported, pasted, recovered, and Codex-authored text is checked immediately.
- The ribbon and Editor Options retain Qt's complete installed multilingual font-family model but use a family-name-only popup, avoiding Qt's surprising appended native-script samples. Latin-capable families render that clean English name in their own typeface; script-only and symbol families use the UI font so their names remain readable.
- Bulleted and numbered paragraphs are backed by session-stable per-list metadata: numbered levels cycle through decimal, uppercase alphabetic, uppercase Roman, lowercase alphabetic, and lowercase Roman styles, repeating over ten levels. Toolbar commands toggle/convert selected paragraphs; hierarchical counters restart and resequence; Enter continues the same list; Shift+Enter inserts a visible soft break with its caret and continuation text aligned to the list text stop; Tab nests through ten levels; Shift+Tab outdents; and an empty item terminates the list. Right-clicking a list exposes List Properties, while the active list also exposes a contextual ribbon tab. Bullet positions and post-marker text gaps are independently configurable for levels 1–10 in space-equivalents and affect only the selected list; built-in defaults are 0/4/8/.../36 and two spaces. The dialog can persist the selected list's ten-level geometry as the application default for new lists. Generated DOCX writes standards-valid native numbering definitions and paragraph `w:numPr` for levels 1–9 without duplicating visual markers into text. Editor level 10 uses literal marker text with equivalent tab/hanging geometry and is recovered by Owl Docs on reopen, but is not native continuation semantics in other editors.
- Authored and supported imported tables are semantic, ordered body blocks rather than tab-delimited text. For the supported simple text-table import shape, the renderer retains authoritative grid widths and table alignment, cell fills and per-side borders, cell padding, vertical and paragraph alignment, mixed direct run formatting, and Word-compatible automatic row metrics. One insertion dialog collects rows, columns, and optional header status. Activating a cell no longer paints the whole table as selected; drag or Shift-click creates a rectangular multi-cell selection. The ordinary character controls (including font, size, emphasis, color, and highlight) and paragraph alignment/justification work within the active cell or across that selected rectangle, including an empty cell's insertion format. Tab/Shift+Tab traverses cells, Tab in the final cell appends one undoable row, and the contextual Table ribbon inserts or deletes rows/columns and offers 13 built-in styles. The selected table can still be moved earlier/later with its handle or keyboard command. The shared renderer draws tables on screen and in searchable PDFs, while new/simplified DOCX saves and SQLite recovery snapshots retain the supported cell formatting, paragraph formatting, structure, and style. Merged, nested, ragged, multi-paragraph, equation-bearing, or image-bearing imported tables remain preserved view-only; merge/split, manual sizing, floating wrapping, and arbitrary imported table-presentation authoring are not yet implemented.
- Safe, bounded PNG/JPEG images referenced by internal `wp:inline` DrawingML relationships render view-only at their positive OOXML extents, with oversized images proportionally reduced to available page width. Their source-boundary positions track surrounding text/equation insertion, replacement, deletion, paragraph split/merge, preview acceptance, undo, and redo without turning the images into editable text characters. External relationships, unsafe paths, unsupported media, missing payloads, and over-limit payloads are not loaded. The OOXML engine/API can author byte-owned PNG/JPEG inline drawings with writer-selected member names and relationship IDs and can reopen their original bytes, names, types, dimensions, and inline order. The desktop Picture command remains a filename placeholder, and image editing, floating/anchored placement, wrapping, crop, and rotation are not supported. Raster signature/container inspection and resource limits run before decode, but the actual decode still occurs in the GUI process and is an explicit hardening gap.
- Equations are native inline atoms backed by the safe `MathAst`. Fractions, roots, scripts, sums, integrals, delimiters, and six matrix delimiters receive vector layout in the shared page renderer; the supported subset serializes as native OMML and reopens as canonical LaTeX without literal marker text. Unsupported OMML remains outside the editable subset and arbitrary TeX commands, packages, filesystem access, and shell escape are never accepted.
- Print preview, standard system printing (all pages, a page range, or the caret's current page), and atomic PDF export all use the same canvas pagination and page-rendering path. Focused headless tests verify page selection, ordering, page geometry, and extractable text when Poppler utilities are installed.
- Optional app-server chat with user activation, managed account login, dynamically listed model/effort/service-tier values, conservative Standard-speed selection, streaming, local SQLite message storage, and live bounded read/preview dynamic tools. Formatting previews are tracked as such when accepted and become one undo transaction.
- Debounced and periodic SQLite recovery checkpoints restore semantic text, direct formatting, native equation atoms, authored tables and cell IDs, table-cell character/paragraph formatting, selected table styles, body-block order, node IDs, and page geometry. Recovery does not retain an imported file's opaque package objects, so a recovered import can only be written as a warned simplified copy at a destination other than the original.
- Same-path saves fingerprint the opened file and refuse to overwrite an externally changed or unreadable destination; the user must choose Save As instead.

## Explicitly not implemented yet

- Desktop UI for authoring embedded images or multiple sections; image editing, floating or anchored images, text wrapping, crop/rotation, shapes, text boxes, charts, or diagrams. The OOXML engine-only inline PNG/JPEG and multiple-section authoring surfaces are described above. Advanced table operations such as merge/split, nested/floating tables, manual row/column sizing, arbitrary custom border/fill/padding authoring, and multi-paragraph cells also remain unimplemented.
- Office Math outside the documented safe subset, arbitrary TeX commands/packages/macros, direct equation-source editing after insertion, and Word-complete mathematical typography or compatibility behavior.
- Style/theme behavior outside the supported `docDefaults`/`basedOn`/theme font-and-color cascade, sparse style authoring/editing, headers/footers, footnotes/endnotes, comments, tracked changes, fields, content controls, and editable complex drawings.
- Full-fidelity recovery of imported opaque content, rulers/navigation panes, an AT-SPI document accessibility tree, incremental background pagination, Skia output, and the published performance gates.
- The Unix-socket MCP helper and destination-capability grant flow. Live `editor.v1` dynamic reads/previews are present, while the file-capability tool denies ungranted requests.
- Hunk-by-hunk preview acceptance, idempotency replay caching, and the complete roadmap tool set (`search`, styles, compatibility, page rendering, save/export requests). The current dynamic surface provides bounded semantic reads, one atomic preview operation batch, and a denied-until-granted file capability.
- Cross-producer Word/Google Docs/Pages interoperability breadth beyond the initial pinned LibreOffice preservation corpus, persistent coverage-guided fuzz campaigns, Word-VM repair checks, signed release packages, complete license review, and an SPDX SBOM.

## Release interpretation

Version 0.2.0 completes the initial M0 feasibility gate set and is suitable for engineering evaluation of the architecture and supported basic-writing slice. The gates are intentionally narrower than production acceptance: they do not establish broad cross-producer layout fidelity, the M1 performance targets, full helper-process isolation, or Word-class behavior. This release should not be presented as a production word processor, a security-hardened document viewer, or a complete M1 alpha.
