# Compatibility matrix

This matrix describes the current executable foundation. “Preserved” means the original package data survives an unchanged Save As or a permitted local text patch; it does not imply that the editor can display or edit that feature. Results are based on the small synthetic test set currently in the repository, not a representative interoperability corpus.

| Feature | Canvas/import behavior | Authoring behavior | DOCX save behavior | Classification |
|---|---|---|---|---|
| Basic body paragraph text | Direct body paragraphs retain their order around supported tables | Editable, including tabs and manual line breaks | New documents serialize text, `w:tab`, and `w:br`; some imported single-`w:t` paragraphs can be patched using their retained source mapping | Narrow editable subset |
| Font family/size, bold, italic, underline, strike, text color, highlight, superscript/subscript | Basic direct run values are transferred to the canvas | Rendered and editable | Serialized for new or explicitly simplified documents | Basic direct-format subset |
| Paragraph alignment, indents, spacing, keep flags, page breaks | Basic direct paragraph values are transferred to the canvas; supported terminal hard `w:br` page breaks produce page boundaries rather than soft line breaks. A break followed by text in the same OOXML paragraph is outside this subset. | Rendered and editable; Ctrl+Enter and supported imported hard breaks paginate consistently on the canvas, in print, and in PDF; new documents default to single line spacing with no automatic paragraph gap | Serialized for new or explicitly simplified documents; safe-patch saves retain the original hard-break XML | Basic direct-format and hard-break subset |
| Page size, margins, orientation | Basic final body-section values are transferred to the canvas | Applied to canvas, print, and PDF; Normal, Narrow, Moderate, Wide, Office 2003, and four-sided custom margins are available | Serialized for new or explicitly simplified documents | Single-section subset |
| Bullets and numbering | Recognized from supported literal markers and Owl Docs' emitted tab-stop/hanging-indent pattern, but not imported as OOXML numbering semantics | Per-list metadata supports ten independently configurable bullet/text stops in space-equivalents (built-in bullet positions 0/4/.../36 and two-space gaps), a persistent “Use as Defaults” action, a context menu and contextual ribbon, aligned wrapped/soft-break lines, hierarchical counter restart/resequencing, continuation on Enter, and nesting on Tab/Shift+Tab. Numbered levels use decimal, uppercase alphabetic, uppercase Roman, lowercase alphabetic, and lowercase Roman styles, then repeat. | Saved as ordinary text with explicit paragraph tab stops and hanging indents; supported geometry is recovered on reopen, while identity and unusual externally edited/non-monotonic level layouts can remain ambiguous without native numbering definitions | List-aware editing scaffold, not an OOXML list implementation |
| Tables | Bounded simple rectangular, single-paragraph-per-cell tables reopen as ordered semantic tables. Their authoritative grid widths and table alignment are used for layout; supported cells retain fills, per-side borders, padding, vertical and paragraph alignment, mixed direct run formatting, and Word-compatible automatic row metrics. Merged, nested, ragged, multi-paragraph, and otherwise advanced tables use view-only paragraph fallbacks while original markup is retained. | Tables have bounded rows/columns, an optional header row, editable cells, body-order movement, and Tab/Shift+Tab traversal; Tab in the final cell appends one undoable row. An active cell or rectangular multi-cell selection accepts the normal character and paragraph-alignment controls. A contextual Table ribbon supports row/column insertion and deletion plus 13 built-in plain, grid, light, medium, accent, banded, and dark-header styles. Merge/split, manual sizing, nested tables, and floating placement remain unsupported. | New and explicitly simplified documents serialize the supported structure, cell text, direct cell character/paragraph formatting, and selected built-in style as native `w:tbl`; the same semantic state is retained in recovery snapshots. Arbitrary imported widths, custom fills/borders/padding, and other presentation details outside this subset are not authored. Eligible paragraph-only edits to imports preserve their original table XML exactly. | Editable rectangular subset with native DOCX persistence; advanced tables preserved/view-only |
| Inline and floating images, wrapping | Safe, bounded raster images reached through internal `wp:inline` DrawingML relationships render view-only at their positive OOXML extents, with oversized images proportionally reduced to the available page width. External, path-traversing, unsupported, missing, and over-limit payloads are not loaded; floating/anchored drawings, wrapping, crop, and rotation are not rendered. Raster bytes are decoded in the GUI process, which remains a hardening gap. | The Picture command inserts a filename placeholder only; images cannot be edited, positioned, or authored as DrawingML. | Original image parts and relationships are preserved only on unchanged or eligible safe-patch saves; simplified/new saves do not author images. | Narrow preserved/view-only inline-raster subset; authoring scaffold |
| LaTeX and Office Math | Supported OMML structures reopen as native equation atoms; unsupported Office Math remains opaque on eligible preservation paths | The non-executing LaTeX subset is canonicalized and rendered as vector math for rows, fractions, roots, scripts, sums, integrals, delimiters, and supported matrices | Supported equations serialize as native inline/display OMML and round-trip without literal LaTeX markers | Editable safe subset; unsupported OMML preserved/view-only |
| Headers, footers, notes, comments | Not displayed | Not editable | Original parts remain opaque on preservation paths | Preserved/view-only |
| Charts, SmartArt, OLE, custom XML | Not displayed | Not editable or executed | Original parts remain opaque on preservation paths | Preserved/view-only |
| Tracked revisions, content controls, fields, hyperlinks | Visible text may be flattened; semantics are not rendered | Not editable as semantic objects | In-place edits in protected contexts are refused; original markup is preserved on preservation paths | Preserved/view-only or blocked |
| Macro-enabled DOCM/DOTM and DOTX templates | Rejected, even when renamed with a `.docx` extension | Not editable | Not saved | Explicitly unsupported |
| ActiveX, OLE, external relationships | Not executed or fetched | Not editable | Preserved as inert package data on eligible preservation paths | Inert opaque content |
| Strict and Transitional namespaces | Basic main-document parsing recognizes both namespace families | Same limited canvas authoring | New files are Transitional; broader Strict behavior is unverified | Parser foundation only |

## Save modes

- **Unchanged imported Save:** does nothing when saving back to the same path.
- **Unchanged imported Save As:** writes the retained original package bytes. A synthetic test verifies byte identity even after the source path is removed.
- **Safe imported text patch:** changes only the character data of a mapped, eligible `w:t` span. The mapper rejects structural edits, signed packages, unsupported text contexts, unsafe whitespace changes, and invalid text. Tests verify unrelated XML and an opaque package member remain unchanged.
- **Simplified Save As:** after formatting or structural changes, the UI requires an explicit confirmation before writing the supported body subset—including authored table structure, cell formatting, built-in styles, and supported equations—and lists known categories that may be lost. It refuses the imported original path, aliases, and existing hard links as the destination.
- **New document save:** writes a small macro-free Transitional DOCX containing body paragraphs, authored native tables with the supported cell formatting and built-in styles, supported OMML equations, the serialized formatting subset above, standard `styles.xml` defaults for the configured font/size and single line spacing, plus a standard `settings.xml` default tab stop derived from the configured space-equivalent width.

Every release should expand this table only from corpus and round-trip evidence. A green unit-test suite is not evidence of universal Word parity.

Unknown or unsupported direct `w:pPr`/`w:rPr` properties are now reported as compatibility warnings and prevent a document from being classified as a fully basic body. Their original XML remains on preservation paths.
